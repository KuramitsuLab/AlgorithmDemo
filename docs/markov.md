# マルコフ連鎖（文字単位 N 次マルコフ）— `docs/markov.html`

夏目漱石『吾輩は猫である』を教材テキストにして、**直前の N 文字から次の 1 文字を確率で選ぶ**だけの
文章生成モデルを、1 文字ずつ動かして観察するビジュアライザ。

---

## 1. 概要 — 何のためのアルゴリズムか

**マルコフ連鎖**は「次の状態は、**直前の状態だけ**で決まる」と割り切った確率モデル。
文章に当てはめると「次の 1 文字は、直前の N 文字だけで決まる」という **N 次マルコフ連鎖**（直前 N 文字を見る、(N+1)-gram モデル）になる。

> **用語の注意（n-gram との対応）**
> n-gram の n は「予測する語を含めた並びの長さ」で、手がかりにする直前の語数は **n−1**。
> - **1-gram（ユニグラム）**は直前を一切見ない。語の出現頻度だけで予測する。
> - **2-gram（バイグラム）**は直前 1 語を手がかりにする。
> - **3-gram（トライグラム）**は直前 2 語を手がかりにする。
>
> 本教材の N は「直前の文字数」なので **N = n−1**（N=1 は 2-gram、N=2 は 3-gram、N=3 は 4-gram）。

これは *文章を書く* ためのアルゴリズムというより、**「言語を確率で扱う」という発想そのもの**を体験するための題材。

- 学習は **本文を 1 回なめて数えるだけ**。微分も勾配降下も出てこない。
- それでも N を 3 まで増やすと、驚くほど「漱石っぽい」文が出てくる。
- 一方で、**意味は一切理解していない**（直前 3 文字しか見ていない）ことも同時に分かる。

現代の LLM も、やっていることの骨格は同じ。

| | マルコフ連鎖（この教材） | LLM |
|---|---|---|
| 見る範囲 | 直前 N 文字（1〜3） | 数千〜数十万トークン |
| 次の確率の求め方 | **数え上げ**（頻度） | **ニューラルネット**が推定 |
| 選び方 | くじ引き・温度・top-k/top-p・貪欲 | **まったく同じ** |

つまり **「次の 1 個を確率で選び、それを入力に戻して繰り返す」** という生成の骨格と、
**温度 / top-k / top-p** という選び方のつまみは、この教材でそのまま学べる。
確率の作り方だけを数え上げ → ニューラルネットに差し替えたものが LLM だ、と理解するとよい。

**関連教材**：`docs/beam.html`（同じ生成を「探索」として見る：貪欲 vs ビームサーチ）、
`docs/nw.html` / `docs/nw2.html`（確率を推定する側＝ニューラルネット）。

## 2. 使い方

### 開き方

```bash
open docs/markov.html
```

外部ライブラリもサーバも不要。テキスト（318,346 字）は HTML に埋め込み済みなので、
ダブルクリックで開けばその場で学習が走る（数十 ms）。

### 画面の見方

| 場所 | 何が見えるか |
|---|---|
| 上のテキスト欄 | 生成された文。**紫の下線**＝書き出し（プロンプト）、**赤**＝いま出た 1 文字 |
| キャンバス上段 | **状態**（直前 N 文字・紫）→ **選ばれた文字**（緑）と、その確率 P |
| キャンバス中段 | 次の 1 文字の**確率分布**（上位 10 種）。バーの長さ＝本文中の出現割合。グレー＋`✕除外` は top-k/top-p で切られた候補 |
| キャンバス下段 | **くじ引きのルーレット**。確率の幅だけ区画を取り、乱数 `r`（赤い▼）が落ちた区画の文字を採用 |
| 右「学習したモデル」 | 状態数・遷移の種類・平均の分かれ道。N や学習量を変えると激変する |
| 右「いまの一手」 | 現在の状態・候補数・採用文字とその確率・エントロピー（迷いの大きさ） |
| 右ヒートマップ | 頻出 18 文字だけの **P(次の文字 \| 直前の文字)**。濃いマスほど続きやすい。赤枠＝いま使った遷移 |

### 操作

- 再生バー：`⏮` `◀ 戻る` `次へ ▶` `⏭` とシークバー。**全ステップを記録している**ので逆再生も自由。
- キーボード：<kbd>←</kbd> <kbd>→</kbd> で 1 文字ずつ、<kbd>Space</kbd> で再生 / 停止、<kbd>R</kbd> で別の文を生成。
- ▶ 再生ボタンは上の操作パネル右端（再生速度スライダの隣）。

## 3. アルゴリズムの概要

### 3.1 学習：本文を 1 回なめて数えるだけ

前処理は、章見出し行・行頭の全角空白・改行を落として **1 本の文字列**にするだけ
（形態素解析はしない。**最小単位は文字**）。

```js
for (let i = order; i < text.length; i++) {
  const s = text.substring(i - order, i);   // 状態＝直前 N 文字
  m.set(s, (m.get(s) ?? "") + text[i]);     // その後ろに来た文字を積む
}
```

`Map<状態, 続いた文字を並べた文字列>` を作るだけ。**確率は保存しない**のがポイントで、
「吾輩は」の後ろに `猫` が 3 回、`人` が 1 回来たなら値は `"猫猫猫人"` になる。
**重複がそのまま頻度**なので、

- 確率が要るときは、その場で数えて `P = n / total`
- くじ引きは、**この文字列からランダムに 1 文字取る**のと同じこと

計算量は O(文字数)、実測 33〜50 ms。全文 318,346 字での規模は次のとおり。

| N | 状態数 | 遷移の種類 | 平均の分かれ道 |
|---:|---:|---:|---:|
| 1 | 3,040 | 44,077 | 14.50 |
| 2 | 44,077 | 128,748 | 2.92 |
| 3 | 128,748 | 204,694 | 1.59 |

**N を上げるほど分かれ道が 1 に近づく**＝ほぼ一本道＝本文の丸暗記に近づく、という
過学習の姿がそのまま数字に出る。

### 3.2 実際の確率分布（全文で学習した場合）

```
P(次 | "吾")     = 輩 89.9%(481) / 人 2.4% / 等 1.1% …     [候補 17 種 / 出現 535 回]
P(次 | "は")     = な 7.5%(514) / 、4.1% / あ 3.0% …       [候補 1020 種 / 出現 6878 回]
P(次 | "吾輩")   = は 38.9%(187) / の 27.9% / が 8.7% …     [候補 25 種 / 出現 481 回]
P(次 | "である") = 。78.9%(759) / か 6.4% / が 5.2% …       [候補 24 種 / 出現 962 回]
```

「吾」の次はほぼ「輩」で迷いがない（エントロピー小）が、「は」の次は 1,020 種類もあって
ほとんど何も決まらない。**N=1 が破綻するのは、この「は」のような状態が大半を占めるから**。

### 3.3 生成：状態を 1 文字ずつずらしていく

```
状態 ← 書き出しの末尾 N 文字
繰り返し:
    候補分布 ← 数えた頻度から P(次 | 状態)
    温度で分布を作り直す        w ∝ P^(1/T),  q = w / Σw
    top-k / top-p で候補を打ち切り、残りで q を割り直す
    乱数 r を引き、累積 q が r を超えた文字を採用（貪欲なら 1 位を採用）
    出力に文字を足し、状態 ← (状態 + 文字) の末尾 N 文字
```

書き出しの末尾 N 文字が本文に存在しないときは、**末尾が一致する状態まで短くして乗り換える**
（バックオフ）。それも無ければランダムな文頭から始め、その旨を説明文に表示する。

### 3.4 フレーム録画方式

このプロジェクト共通の作りとして、生成は**全ステップのスナップショットを配列に記録**してから描画する。
描画は「i 番目のフレームを引く」だけなので、**逆再生・シーク・一時停止がすべて自然に成立**する。
乱数はシード固定（`mulberry32`）なので、同じ設定なら**何度でも同じ文**が出る（`R` でシードを引き直す）。

## 4. 試してみると面白いこと

### ① N を 1 → 2 → 3 と上げる（いちばん大事な実験）

書き出し「吾輩は」のまま N だけを変える（初期状態のまま、下の文がそのまま再現できる）。

```
N=1  吾輩はなって、とく滑れでの切りしょっと心で、してからんだと思うかしない種類が度は生徒は和唐縮していると…
N=2  吾輩はこの際に……ふとそれを妨害するさ」と東風君の事です。これでなくて飲めの男がある。此発作的になって…
N=3  吾輩はこの問題を提供して自然の勢夫と衝突する。「私しの名は、当時は何と称する私立の中学校——八百の健児との…
```

- **N=1**：文字の"つながり癖"だけ。単語にすらならない
- **N=2**：単語のかたまりと会話文の形が立ち上がる
- **N=3**：一見、漱石の文（ただし本文の断片をつなぎ合わせているだけ）

**どこから "日本語らしさ" が生まれるのか**を、N を上げ下げしながら体感するのがこの教材の核心。

### ② 貪欲（最頻）にして暴走させる

「選び方」を **貪欲** にすると、必ずこうなる。

```
「そのである。「そのである。「そのである。「そのである。…   (N=1)
「それでもない。「それでもない。「それでもない。…            (N=2)
```

状態が同じなら必ず同じ文字を選ぶので、**一度ループに入ると二度と抜けられない**。
「いつも一番いい手を選ぶ」ことの弱点であり、`docs/beam.html` の貪欲法の失敗とまったく同じ話。

### ③ 温度を上げて壊し、top-k で救う

- `T = 1.8` そのままサンプリング →「…α1) での顔中かが重しか孔を…」と**記号や珍しい漢字が混ざって崩壊**
- `T = 1.8` のまま **top-k = 5** →「…そうに、これていたのからないた。…」と**崩れない**

温度を上げると、本文中に 1 回しか出ない裾の候補まで太ってしまう。
それを **切り落とすのが top-k / top-p** だと目で確認できる。

### ④ top-k と top-p の違いを「残した候補数」で見る

右カードの「絞り込み後」を見ながら生成すると、

- **top-k=5** … いつでもきっちり 5 種（分布の形を無視）
- **top-p=0.8** … 平均 60 種、`p=0.5` なら平均 11.8 種。**状態によって数が変わる**

「である」の次のように答えがほぼ決まっている（`。` が 78.9%）ときは top-p は候補を数個しか残さず、
「は」の次のように迷っているときだけ広く残す。**分布の尖り具合に合わせて自動調整**されるのが top-p。

### ⑤ 学習量を減らして「丸写し」を作る

学習量を **2 千字**にして N=3 にすると、平均の分かれ道は **1.12**。
つまりほとんどの状態で次の文字が 1 通りしかなく、**本文をそのまま吐き出すだけ**の機械になる。

| 学習量 | N=1 の分岐 | N=2 の分岐 | N=3 の分岐 |
|---:|---:|---:|---:|
| 2 千字 | 3.57 | 1.42 | 1.12 |
| 1 万字 | 4.88 | 1.69 | 1.21 |
| 5 万字 | 7.58 | 2.11 | 1.36 |
| 全文 (31.8 万字) | 14.50 | 2.92 | 1.59 |

**データが足りないと丸暗記になる**＝過学習。「Nを上げれば良い」わけではなく、
**N とデータ量のつり合い**で決まることが表からも読み取れる。

### ⑥ 書き出しに現代語を入れてみる

`コンピュータ` と入れると、N=1 では状態は末尾 1 文字の **「タ」** だけ（＝直前 1 文字しか見ていない証拠）。
N=3 では「ュータ」が本文に無いので **「ロータ」** のように末尾 2 文字が一致する状態へ乗り換える（バックオフ）。
`AI` のように本文にまったく無い文字ならランダムな文頭から始まる。
**モデルは学習した文字しか知らない**ことが体験できる。

### ⑦ ヒートマップを眺める

`。` の行を見ると `「` が濃い（会話が始まる）、`で` の行は `あ`（＝「である」）が濃い、など、
**日本語の癖が行ごとの模様**として見える。N=1 のモデルの正体はこの 1 枚の行列である。

## 5. 各パラメータの意味

### 文脈長 N（直前の何文字を見るか）

| 値 | 意味 | 起きること |
|---|---|---|
| `N = 1`（2-gram） | 直前 **1 文字**だけで次を決める | 状態 3,040 個。候補が広すぎて意味不明な文になる |
| `N = 2`（3-gram） | 直前 **2 文字** | 単語のかたまりが見え始める |
| `N = 3`（4-gram） | 直前 **3 文字** | 文らしくなる代わりに、本文の丸写しに近づく |

大きいほど「賢く」なるが、**状態数が爆発**し（3,040 → 128,748）、
1 状態あたりのデータが薄くなって新しい文を作れなくなる。この綱引きが n-gram の本質。

### 書き出し（プロンプト）

生成の起点。ここに入れた文字列の**末尾 N 文字**が最初の状態になる（それ以前は見ていない）。
空欄にすると、本文中の文頭（`。` や `」` の直後）からランダムに開始。
LLM のプロンプトと同じ役割だが、**効くのは末尾 N 文字だけ**という点が決定的に違う。

### 選び方

| 選択肢 | 中身 | 向いている用途 |
|---|---|---|
| **そのままサンプリング** | 全候補を確率どおりの幅にしてくじ引き | 素のモデルの実力を見る |
| **top-k** | 確率上位 **k 種**だけ残し、その中で割り直してくじ引き | 崩れを防ぐ。候補数は常に固定 |
| **top-p**（核サンプリング） | 確率を上から足して **p%** に届くまでの種だけ残す | 迷っている時だけ候補を増やす。LLM の既定に近い |
| **貪欲** | 常に確率 1 位（温度 0 の極限） | 「最善手だけ選ぶ」ことの失敗を見る |

### 温度 T（0.1〜2.0）

確率の**とがり具合**を変えるつまみ。`w ∝ P^(1/T)` として作り直す。**選び方（くじの引き方）は変えない**。

| T | 分布 | 出てくる文 |
|---|---|---|
| → 0 | 1 位だけが立つ | 貪欲と一致。同じ文の繰り返し |
| 0.5 | とがる | 無難。「それである」的な定型が増える |
| 1.0 | **本文の頻度そのまま** | 素直 |
| 1.8 | 平坦に近づく | 珍しい文字も出て破綻しやすい |

画面では、**確率バー＝生の確率 P**、**ルーレットの幅＝温度をかけた q** と描き分けてある。
T をずらすと「バーは同じなのにルーレットの幅だけ変わる」＝温度の仕事が一目で分かる。

### k（top-k 選択時、1〜30）

残す候補の**個数**。`k=1` は貪欲と同じ。`k=2〜5` で安全側、大きくすると素のサンプリングに近づく。
分布が尖っていようが平坦だろうが**同じ個数**しか残さないのが長所（安定）であり短所（融通が利かない）。

### p（top-p 選択時、0.05〜1.00）

残す候補の**確率の合計**。上位から足して p に届いた時点で打ち切る。
`p=1.00` は素のサンプリングと同じ。小さくするほど保守的。
**候補の個数は状態ごとに変わる**（例：全文 N=1 で `p=0.8` なら平均 60 種、`p=0.5` なら平均 11.8 種）。

### 学習量（コーパス）

先頭から何文字を学習に使うか（全文 / 5 万字 / 1 万字 / 2 千字）。
減らすほど**丸写し**が増える。N と組み合わせて「データ量 vs モデルの複雑さ」を見るためのつまみ。

### 生成する文字数 / 再生速度 / 🎲 別の文を生成

- **生成する文字数**（80 / 150 / 300）… 記録するフレーム数。長いほど貪欲のループや破綻がよく見える。
- **再生速度** … 自動再生の間隔。1 文字ずつ観察するときは遅く。
- **🎲 別の文を生成**（<kbd>R</kbd>）… 乱数のシードだけを引き直す。モデルも設定もそのままなので、
  **同じ設定で何通りの文がありうるか**を見るのに使う。

## 付録：まとめのひとこと

> 数えるだけで、これだけ「それらしい」文が書ける。
> しかし、直前 3 文字しか見ていないので、意味も文脈も持っていない。
> この「確率で次を選ぶ」骨格はそのままに、**確率の求め方をニューラルネットに置き換えた**のが LLM である。
